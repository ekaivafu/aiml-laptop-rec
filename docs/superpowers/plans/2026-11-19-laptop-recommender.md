# Laptop Recommendation System Implementation Plan

**Goal**  Build a browser-based college demo where a user sets their INR budget, primary use case, and optional hardware preferences, then sees the best match and up to four alternatives from the Indian laptop catalog.

**Architecture**  Reuse the SQLite scraper pipeline and its two CSV exports. Join observed catalog data with the existing engineered use-case scores. Keep filtering and ranking in a shared Python module called by the webpage and the evaluation script. Compare with cheapest-first on the same eligible set.

**Stack**  Python, pandas, scikit-learn, Streamlit, pytest. Run the webpage locally for the demo. Keep `scraper.py` as the data collection and export entry point.

## 1. Refresh and audit the catalog

- [ ] Run `python -m pytest tests -q` before changes. The system Python passed all 14 tests during planning. The bundled `venv` lacked pytest, so document a clean install and include the new dependency and test setup in `requirements.txt` or a dedicated dev requirements file.
- [ ] Preserve the SQLite snapshot and run `python scraper.py export` from the project root. The snapshot contained 744 catalog rows and 744 uniquely keyed feature rows. Of those, 688 had positive catalog prices and 56 had missing catalog prices with a positive imputed feature price. Both CSV exports still held 28 rows during planning. Record the actual counts after export.
- [ ] Implement `load_catalog(catalog_path: Path, features_path: Path) -> pd.DataFrame` in `recommender.py`. Strip header whitespace, validate required columns, and enforce a one-to-one join on `laptops.csv.id = laptops_ml_ready.csv.laptop_id`. Surface unmatched IDs or duplicate keys as a data error. Bring in the feature scores and `score_confidence`. Use catalog values for prices, hardware shown to users, and shop links. Check that required score columns are finite and within 0–100.
- [ ] Record data source, snapshot date when known, missingness and duplicate checks, and the final count of eligible products in `README.md`. Keep `data/exports/raw_laptops.csv` out of this workflow because a generator uses that path for synthetic rows. Treat all prices as snapshot prices. The existing database is sufficient to start the demo while the pending scrape queue remains optional.

## 2. Implement and test the ranking

- [ ] Implement `filter_catalog(catalog: pd.DataFrame, budget: int, *, brands: tuple[str, ...] = (), min_ram_gb: int | None = None, min_storage_gb: int | None = None) -> pd.DataFrame` in `recommender.py`. Require a positive budget and keep only finite positive catalog prices at or below it. Selected brands are alternatives within the brand filter. Combine active filters with AND. Use observed RAM and storage for minimums. A missing specification fails only when its corresponding filter is active.
- [ ] Implement `recommend(eligible: pd.DataFrame, use_case: str, top: int = 5) -> pd.DataFrame` in `recommender.py`. Map `gaming`, `aiml`, `video-editing`, `programming`, `student-office`, `portability`, and `value` to the corresponding `score_*` columns in `pipeline/feature_engineer.py` (`aiml` maps to `score_aiml`, and `value` to `score_value_for_money`). Validate the use case and require a positive result count.
- [ ] Use Euclidean nearest-neighbor search on the selected use-case score and value score, both divided by 100. Scale the dimensions by `sqrt(0.8)` and `sqrt(0.2)`, then query the correspondingly scaled ideal point `(1, 1)`. For `value`, use its score alone. Rank by distance ascending, then confidence descending, catalog price ascending, and numeric `laptop_id` ascending. Resolve ties before slicing to `top`. Return an empty frame when there are no eligible matches.
- [ ] In `tests/test_recommender.py`, use small offline fixtures to cover padded headers, missing files or required columns, duplicate or unmatched IDs, an unknown catalog price with an imputed feature price, exact budget inclusion, over-budget exclusion, combined filters, missing specs with and without an active minimum, a switch in ranking when the use case changes, deterministic ties, fewer matches than requested, and no matches. Run `python -m pytest tests -q`.

## 3. Build the webpage

- [ ] Add Streamlit to `requirements.txt` and add `streamlit_app.py` at the project root. Resolve both export paths relative to that file. Load the snapshot locally, populate brand options from the catalog, and show an actionable message with `python scraper.py export` if the exports are missing or invalid. Search should require no network calls, including requests to retailers.
- [ ] Put a compact, labeled form under the page title. Include a maximum budget in INR, one primary use case, and optional selectors for brands, minimum RAM, and minimum storage. Group hardware filters under “More filters.” Use a single “Find laptops” submit button and call `filter_catalog` followed by `recommend` on submission. Show a summary of the submitted filters with the results so users can tell which selections were applied.
- [ ] Feature the first result as “Best match,” then list up to four alternatives. Each result shows model, snapshot price in INR, CPU, GPU, RAM and storage when available, and a short reason tied to the use case and observed specs. Show a shop link when the catalog contains a valid HTTP(S) listing URL. Display missing specs as “Unknown” and add a short note that prices may have changed. If the filters match zero laptops, keep the selected filters and explain which ones users can adjust. Stack results vertically on small screens and keep labels visible.
- [ ] Add `tests/test_streamlit_app.py` using Streamlit `AppTest` and a small fixture catalog. Submit a search, check that the best match renders, change filters and resubmit, and verify an empty result clears the previous results. Run `python -m streamlit run streamlit_app.py` and check both desktop and mobile widths. Try ₹60,000 Student / Office, ₹90,000 Gaming, and a restrictive combination with zero matches.

## 4. Evaluate and prepare the submission

- [ ] Create `evaluation/scenarios.csv` for six use-case and budget combinations and `evaluation/RESULTS.md` for the method and findings. For each scenario, define a hardware suitability rubric before viewing ranks. Pool the top five from the recommender and the cheapest-first baseline, hide method and rank, and label the pooled laptops using observed specifications. Treat missing required evidence as unknown and report that count. Save the rubric and labels so the comparison can be repeated.
- [ ] Add `scripts/evaluate_recommender.py` to create one eligible set per scenario using `filter_catalog`, run both methods against that set, and check for filter violations. Report shortlist coverage and the fraction of returned results judged suitable for each method, using actual returned count as the denominator and reporting unknown labels separately. For no-result scenarios, report coverage and leave the suitability fraction undefined. Describe the judgment sample size and limitations. Measure both methods and report the observed result even if cheapest-first wins a scenario.
- [ ] Explain in `README.md` that the feature engineer supplies heuristic scores and nearest-neighbor search uses those scores to match a use case. They are proxies for suitability. If the course explicitly requires a trained model, add a separate price-estimation experiment using real positive snapshot prices only. Split by laptop model family before fitting preprocessing, compare with a training-median baseline using held-out MAE in INR, and exclude price-derived features. The existing `Laptop_Price_Evaluation.ipynb` can be a starting point after replacing its synthetic-capable input. Price prediction remains separate from recommendation evaluation.
- [ ] Verify from a clean environment that the README setup and webpage launch commands run, the full offline tests pass, and saved evaluation results can be regenerated. Document any unresolved data quality issues and include two example search presets in the submission README. The demo is ready when a user can open the webpage, submit filters, and get a ranked shortlist with explanations or a clear empty state.
