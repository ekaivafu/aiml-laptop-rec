# Build: India-Specific Laptop Dataset Collection Pipeline

## Role

Act as a senior Python data engineer specializing in web data collection, data cleaning, normalization, and ML dataset preparation.

I am building a resume-level **AI/ML laptop recommendation system focused on the Indian market**.

Your job right now is ONLY to build the **data collection pipeline**.

Do NOT build the recommendation model yet.

Do NOT build any frontend, dashboard, website, charts, GUI, or admin panel.

I only need **pure, clean, structured laptop data** that I can later use to train/build the recommendation system.

The only interface should be the **terminal/CLI**.

---

# 1. Main Goal

Build a robust scraper/data pipeline that can collect approximately:

**2,000–3,000 unique Indian laptop configurations**

from multiple legitimate/publicly accessible Indian sources.

Potential sources:

* Flipkart
* Amazon India
* Croma
* Reliance Digital
* Smartprix
* Other suitable Indian laptop retailers/catalogs where legitimate and permitted

Before implementing a collector for a source, verify that automated collection is allowed and that the required data is publicly accessible.

Do NOT bypass:

* CAPTCHAs
* authentication
* access controls
* anti-bot protections
* rate limits
* robots restrictions
* Terms of Service

If a source cannot be legitimately automated, make that source optional/disabled rather than attempting to bypass restrictions.

```text

    flipkart/
```

# 8. Raw Data

Always preserve the original scraped values.

Example:

```text
raw_ram = "16GB DDR5-4800 RAM"
```

Then parse it into:

```text
ram_gb = 16
ram_type = DDR5
ram_speed_mhz = 4800
```

Do NOT throw away the raw value.

This allows us to improve parsers later without scraping the website again.

Store raw and structured data separately.

# 10. Normalization

Create a reusable normalization layer.

Examples:

```text
₹79,990
Rs 79,990
79990

→ 79990
```

```text
512 GB
512GB
0.5 TB

→ 512 GB
```

```text
2300 g
2.3 kg

→ 2.3 kg
```

```text
RTX 4050
NVIDIA GeForce RTX 4050
RTX4050 Laptop GPU

→ RTX 4050
```

```text
Intel Core i7 13620H
Intel i7-13620H
Core i7 13th Gen 13620H

→ Intel i7-13620H
```

Normalize casing, whitespace, units, currency, CPU names, GPU names, RAM, storage, display resolution, etc.

---

# 11. Deduplication

The same laptop can appear on multiple websites.

Example:

```text
Flipkart:
ASUS TUF A15 FA507NUR

Amazon:
ASUS TUF Gaming A15 FA507NUR

Croma:
ASUS TUF A15 FA507NUR
```

These may be the same configuration.

Use a canonical identity based on fields such as:

```text
brand
model_number
CPU
RAM
storage
GPU
display
```

Prefer model number when available.

Use fuzzy matching only when necessary.

Do NOT blindly merge ambiguous records.

If uncertain, flag the record for review.

---

# 12. Preserve Multiple Sources

Deduplication should NOT delete source-level information.

One laptop should be able to have multiple price records:

```text
Laptop:
ASUS TUF A15 FA507NUR

Flipkart → ₹79,990
Amazon → ₹81,499
Croma → ₹82,990
```

Therefore use separate conceptual entities:

```text
Laptop
Price Observation
Source
```

---

# 13. Price History

Design the system so repeated scraping does NOT overwrite old prices.

Example:

```text

```

Each observation should include:

```text

```

This will later allow us to calculate:

* current price
* average price
* lowest price
* price trend
* discount from recent average

# 14. Missing Data

Missing data is acceptable.

Example:

```text
battery_wh = NULL
```

Do not discard the whole laptop just because one field is missing.

If a field is missing from one source, optionally try to enrich it from another legitimate source.

Example:

```text
Flipkart
    ↓
battery missing
    ↓
trusted second source
    ↓
battery found
```

Track the provenance of enriched information.

Never invent hardware specifications.

# 15. Validation

Before accepting a record into the final dataset, validate it.

Examples:

### Price

* positive
* valid currency
* detect obviously suspicious values

### RAM

* plausible capacity
* valid RAM type

### Storage

* positive
* correct units

### Display

* plausible screen size
* valid resolution
* plausible refresh rate

### GPU

* known/valid model
* plausible VRAM
* detect parsing mistakes

### CPU

* valid model format
* plausible cores/threads

Use:

```text
valid
warning
invalid
```

rather than silently deleting suspicious records.

# 16. Retry System

Temporary failures should be retried.

Example:

```text
Attempt 1 → failed
Attempt 2 → failed
Attempt 3 → success
```

After the configured retry limit:

```text
status = failed
error_reason = ...
```

Do not retry indefinitely.

Do not implement anti-bot evasion.
